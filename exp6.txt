Username: student
Password: labpass2026
Successful status: 302

Step 1
In the terminal:
open login

This tells the simulator:

> Target route = `/login`

### Step 2
Open the **dedicated login target** from the experiment page.

You'll get a login form.

### Step 3
Enter:

Username: student
Password: wrong

The password can be an incorrect one because we're trying to capture an unsuccessful request.

# PART 2 — Capture the request in Proxy

### Step 4
Open the embedded **Burp Suite**.

### Step 5
Go to:

**Proxy → Intercept**

### Step 6
Turn:

**Intercept OFF → ON**

⚠️ **Do this BEFORE clicking Login.**

### Step 7
Go back to the login page.

Click:

**Login**

Burp should intercept the HTTP request.

You'll see something roughly like:

POST /login
...
username=student&password=wrong

# PART 3 — Send request to Intruder

Step 8
In the intercepted request, choose:

**Send to Intruder**

Step 9
Open:

**Intruder**

Step 10
Go to the **Positions** section.

You'll see the captured request.

It may look approximately like:

```text
username=student&password=wrong
```

---

# PART 4 — Select ONLY the password

### Step 11
Clear any automatically selected payload positions.

### Step 12
Select ONLY:

```text
wrong
```

which is the password value.

### Step 13
Click:

**Add §**

You want the request to look like:

```text
username=student&password=§wrong§
```

Only the **password value** gets the `§` markers.

# PART 5 — Configure the wordlist

### Step 14

Go to:

**Intruder → Payloads**

### Step 15

Make sure the payload type is the appropriate **simple/list payload** option.

### Step 16

Load the supplied:

wordlist.txt

You **do not create this file yourself**.

The lab supplies it.

### Step 17

You'll see the password candidates loaded into the payload list.

# PART 6 — Start the attack

Step 18

Start the Intruder attack using the lab's **Start attack** control.

Burp will test the passwords from `wordlist.txt` against:

username=student

while changing only:

password=...

---

# PART 7 — Find the successful response

### Step 19

Look at the Intruder results table.

You'll have multiple attempts.

Look at the **Status** column.

Most failed attempts will have the unsuccessful response.

One successful attempt will have:

```text
302
```

In **your lab**, the successful password was:

```text
labpass2026
```

So you'll find something corresponding to:

```text
Payload: labpass2026
Status: 302
```

---

# PART 8 — Record the status

### Step 20

Go back to the simulator terminal.

Enter:

```bash
status 302
```

You got:

```text
Successful redirect status recorded.
```

🎯 **Objective 4/5 complete.**

### 🧠 Why 302?

HTTP **302 = Found / temporary redirect**.

In this lab, a successful login produces a redirect, so **302 is the indicator of successful authentication**.

---

# PART 9 — Confirm the password

### Step 21

Now submit the recovered password:

```bash
answer labpass2026
```

You got:

```text
Evidence answer recorded.
```

🎯 **Objective 5/5 complete.**
